# Личный агент владельца — правила репозитория (27.11.2026)

Личный агент владельца по образцу muse: умеет то же, что muse (разговор, файлы, исполнение кода, браузер, память, цели, расписания, навыки, мессенджер), но **модель меняется одной настройкой**: Claude, OpenAI или локальная модель на своём компьютере (Ollama, LM Studio, llama.cpp, vLLM). Агент не зависит ни от Claude Agent SDK, ни от Claude Code, ни от одного поставщика.

Это отдельный проект. С Zoe (ai-retail-brain-*) он не связан: данных сетей, 1С, групп и людей сетей здесь нет и не будет.

## Кто работает

- **Владелец** — решает, что делаем. Его слово — строка плана в том же ходе.
- **Ревизор** — держит план `docs/PLAN.md`, пишет карточки, читает каждый срез инженера и даёт «Ок» или замечание, вливает в `main`. Код не пишет; коммитит только `docs/`.
- **Инженер** — пишет код срезами по карточкам ревизора, в своей ветке, со своими тестами.

Раздача: ревизор сам даёт инженеру следующую строку плана. Владельцу пишут только когда нужно его слово или шаг готов.

## Мерило — muse

1. До кода — вопрос «как это у muse?», и ответ прочитан в его тексте или ядре: в описании среза названы файл и строка.
2. У muse вещь есть — берём его форму. Нет — у нас её тоже нет. Своих пределов, сторожей, порогов и «на всякий случай» не добавляем.
3. Исключение одно, и называется в срезе словом «исключение»: прослойка модели (у muse модель одна, у нас — любая).

Где muse (только чтение, ничего не менять и не копировать в облако):
- снимок файловой системы живого muse 25.11: `zoe-ci:~/muse-live-src/rootfs-full` (опись — `rootfs-full.listing.txt`); тексты движка — `opt/hatch-private/prompts/`, конфиги — `opt/hatch-private/configs/`, навыки — `opt/hatch/`;
- ядро — `zoe-ci:~/muse-live-src/core-v2/hatch-2026-11-25-v2.bin`, его разбор — `core-v2-analysis/`; кода движка в снимке нет — устройство читается в ядре и разборе;
- закрытый GitHub `iseethepoint/muse-live` — то же самое.
- Данные пользователя muse (`home/hatch/agents`, `home/hatch/workspace`) в репозиторий не идут.

Второй образец, только чтение: `~/ai-retail-brain-v3` (Zoe) — как мы уже пересобрали muse на Python (область файлов, память, навыки, инструменты, провод). Оттуда можно брать общее; всё про сети, 1С, группы, перемещения — не брать. Его цикл хода стоит на `claude_agent_sdk` — **этого здесь нет**, цикл свой.

## Устройство

- `agent/loop` — свой цикл хода: модель → вызовы инструментов → результаты → модель, сжатие длинного разговора, подагенты.
- `agent/model` — **единственное место, где агент говорит с моделью.** Один вход (сообщения, инструменты, настройки) → один выход (текст, вызовы инструментов, счёт токенов). Поставщики:
  - `anthropic` — официальный SDK `anthropic` (Messages API), по умолчанию `claude-opus-5-5`, мышление `adaptive`;
  - `openai_compat` — всё, что говорит «как OpenAI»: OpenAI и локальные серверы (Ollama, LM Studio, llama.cpp, vLLM) — по адресу `base_url`.
  - Что у поставщика нет (кэш подсказки, мышление, встроенный поиск), прослойка не подделывает: возможность просто не включается, и это видно в настройке.
- `agent/tools` — инструменты как у muse; описание инструмента одно на всех поставщиков.
- `prompts/`, `skills/` — тексты muse с названными отличиями.
- Настройка модели — один файл `config/model.toml` (поставщик, модель, адрес); ключи — только в переменных окружения, в репозиторий не идут.

## Как работаем

- Срез — одна вещь. Ветка `e/<строка>-<коротко>`, коммит: Что / Зачем / Основание (строка плана, файл:строка muse) / Проверка / Исполнитель.
- Проверка одна — тесты на каждый срез; тест красный на подмене (без среза падает). Экзаменов, репетиций и замеров «до и после» нет.
- Каждый тест прогоняется на двух поставщиках: подделка `anthropic` и подделка `openai_compat` (записанные ответы). Живые вызовы моделей — только по слову владельца, это деньги.
- «Ок» ревизора — только после чтения diff этого sha. Вливает ревизор, без `push -f`.
- Неиспользуемое после правки удаляется в том же срезе.
- Ничего не в облако, кроме вызова выбранной модели. Секреты не печатать.
- Язык общения — русский, простыми словами; идентификаторы — как в коде.
