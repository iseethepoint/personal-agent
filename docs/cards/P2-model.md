# Карточка П2 — модели как у muse (`agent/model`)

**Кто читает:** ревизор и инженер. На П2 стоят цикл хода (П3) и все инструменты (П4).
**Решение:** как агент говорит с любой моделью: реестр моделей с умениями, выбор модели по задаче, два поставщика.
**Нормально:** форма реестра и выбора повторяет `hatch-inference` muse. Одинаковый вход даёт одинаковый выход у обоих поставщиков. Умение, которого у модели нет, не подделывается, а выключается, и это видно в реестре.
**Стоит на:** `docs/muse_inventory.md` — разделы 1 (находка 2), 3 (привязки к модели) и 4.1; CLAUDE.md, «Модели — как у muse».
**Как обманет:** своя придуманная схема настроек вместо `[defaults]` / `[weights.*]` / `[[models]]` muse; умение «включено», а поставщик его молча игнорирует; тесты зелёные и без среза; живой вызов модели в тестах.

## Общее для всех срезов

- Первый код репозитория: cargo workspace в корне, крейт `agent/model` (имя пакета `agent-model`). Rust stable, `cargo test` и `cargo clippy -- -D warnings` чистые.
- Ключи — только из переменных окружения (имя переменной записано в реестре). В реестр, тесты и логи ключи не попадают.
- Сеть в тестах — только поддельный HTTP-сервер на `127.0.0.1` с записанными ответами (файлы в `agent/model/tests/fixtures/`). Записанные ответы составлять по документации API, а не по живым вызовам.
- В коммите, в строке «Основание», — файл:строка muse из описи.

## П2а — реестр и выбор модели (без сети)

Ветка `e/P2a-registry`.

1. Прочитать реестр muse целиком: `core-v2-analysis/strings-all.txt:235532-237160` (разделы `[defaults]`, `[weights.*]`, `[wires]`, `[[models]]`, `setup.default_model_purposes`, `setup.overrides`). Разбор: `source-files.txt:5318` (`model_registry.rs`), `model_registry_file/load.rs`, `model_resolver/*` (`:5320-5330`), `agent_manager/control/model_resolution.rs`.
2. Файл реестра агента — `config/models.toml`, той же формы, что у muse:
   - модель — запись с поставщиком, именем модели у поставщика, адресом `base_url` (для `openai_compat`), именем переменной ключа;
   - веса — окно, предел ответа, умения. Названия умений — как у muse (`adaptive_thinking`, `compaction`, `tool_search`, `output_effort`, `image_resolution`, `runtime_output_ceiling`, `mid_conversation_system_messages`), а для `openai_compat` — по смыслу его флагов: зрение, допустимые форматы картинок, флаг ошибки инструмента, мышление, параллельные вызовы. Флаг `local_inference` — как у muse (`strings-all.txt:235901`);
   - задачи — `main`, `maintenance` (сжатие и сброс памяти), `background`, `cron`, `self_improvement`, `browser`, `media_description`, `embeddings`. Имена задач сверить с `setup.default_model_purposes` (`strings-all.txt:237127-237137`) и брать имена muse там, где они есть.
3. В коде: загрузка и проверка реестра. Ошибкой считаются ссылка на модель, которой нет, задача без модели, порог больше окна (как `0x20954580` у muse). Ещё в коде: выбор модели по задаче и переопределение модели для задачи (форма `setup.overrides`).
4. Типы одного входа и выхода — без поставщиков, но окончательные:
   - вход — сообщения (роли, текст, картинки, вызовы инструментов и их результаты с признаком ошибки, блоки мышления), инструменты (имя, описание, JSON Schema), настройки (предел ответа, сила, обязательный инструмент);
   - выход — текст, вызовы инструментов, мышление (как есть, для возврата в историю), причина остановки, счёт токенов (вход, выход, из кэша);
   - ошибка поставщика — единым видом с признаком «можно повторить» (форма `provider_error.rs`, `source-files.txt` в разделе 4.1 описи).
5. Тесты: пример реестра с моделями `anthropic` и `openai_compat` (локальная — по адресу) загружается; каждая ошибка из пункта 3 ловится; выбор по задаче и переопределение работают.

## П2б — поставщик `anthropic`

Ветка `e/P2b-anthropic`, после «Ок» на П2а.

1. Форма — `hatch-inference/src/model/anthropic/*` (`source-files.txt:5263-5275`): перевод подсказки и инструментов, запрос, поток SSE, ответ, ошибка HTTP, бюджет размера запроса. HTTP — свой клиент на Messages API, как у muse (`request_flow`, `parse_sse_stream`, `sse_parser_state_machine`). Версия `anthropic-version: 2023-06-01` (`strings-all.txt:237329`). Официального SDK Anthropic на Rust нет — это отличие от фразы CLAUDE.md про «официальный SDK», назвать его в коммите.
2. Поток SSE: текст, `tool_use` (с частями JSON), мышление (`thinking`, `redacted_thinking` — возвращаются в историю как есть), `usage` с кэшем. Обрыв потока даёт ошибку поставщика с признаком «можно повторить».
3. Умения — только по флагам реестра: `thinking: adaptive`, `effort`, `cache_control` на неизменном начале подсказки. Если флаг выключен, поле не отправляется.
4. Тесты (поддельный сервер): ответ текстом; ответ с двумя `tool_use`; мышление туда и обратно; ошибка 429 и 500 (можно повторить), 400 (нельзя); обрыв потока; выключенный флаг — поля нет в запросе.

## П2в — поставщик `openai_compat`

Ветка `e/P2c-openai-compat`, после «Ок» на П2б.

1. Форма — `kimi_chat_completions/*` (`source-files.txt:5301-5304`): Chat Completions, `tools`, `tool_choice`, `parallel_tool_calls`, SSE до `[DONE]` («stream ended before [DONE]», `strings-all.txt:237328`). Адрес — `base_url` из реестра: OpenAI, Ollama, LM Studio, llama.cpp, vLLM — один код.
2. Перевод: вызовы — `tool_calls` (части аргументов в потоке склеиваются), результаты — роль `tool`; ошибка инструмента — текстом результата (флага нет, опись, раздел 3); картинки — `image_url` с data-адресом, только если в реестре включено зрение; мышление — `reasoning_effort` и `reasoning_content`, только по флагу; счёт токенов — `usage` с `cached_tokens`, а если сервер `usage` не отдал — ноль и пометка.
3. Эмбеддинги — `/v1/embeddings` для задачи `embeddings` (у muse — служба `embeddings`, 384 измерения, cosine; опись, раздел 3).
4. Тесты: тот же набор, что в П2б, на записанных ответах `openai_compat`, плюс ответ без `usage`, сервер без инструментов (ошибка при запуске, а не подделка) и эмбеддинги. Общий тест для П2б и П2в: одинаковый вход даёт одинаковый выход.

**Сдача:** каждый срез — своя ветка и свой sha ревизору; следующий срез начинается после «Ок» на предыдущий.
