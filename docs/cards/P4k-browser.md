# Карточка П4к — живой браузер

**Кто читает:** ревизор и инженер.
**Решение:** как Hamlet ведёт настоящий браузер: главный агент отдаёт задачу окну, исполнитель (отдельный агент на модели задачи `BrowserAgent`) ведёт страницу и отчитывается.
**Нормально:** форма — muse (`browser.browse`, `browser.windows`, исполнитель со своими инструментами и текстами); описания и тексты — из ядра и `prompts/browser/`, с правками П10; браузер — свой Chromium через CDP.
**Стоит на:** опись 2.11; `tool-schemas.txt:2-23` (схемы `browser.browse/windows`); `source-files.txt:914-…` (`hatch-agent/src/browser/*`, 90 файлов), `:1475-1503` (`browser_delegate/*`); тексты `P/hatch-agent/prompts/browser/` (163: `system.md`, `instructions/`, `guidance/`, `handoff/`, `completion_gate/`, `tools/*.json|md`); `R/home/hatch/docs/browser.md`.
**Как обманет:** исполнитель «работает» только на подделке страницы; свои инструменты исполнителя вместо muse; окно, которое не переживает следующую команду главного агента.

Браузер у muse огромный — по срезам:

## П4к-1 — окна, исполнитель, основные действия

Ветка `e/P4k1-browser`.

1. Главный агент: `browser.browse` (новая работа или продолжение окна по `task_id`, `tab`, `profile`, `answer_to`) и `browser.windows` (список, профили, закрыть вкладку/окно) — описания и поля из ядра; итог окна приходит в ящик, как у подагентов (П3г).
2. Исполнитель: подагент на модели `BrowserAgent` (П2а), системный текст `prompts/browser/system.md` + `instructions/`, `guidance/`, `pages.md`; инструменты исполнителя — по `prompts/browser/tools/*.json` muse: действия на странице (`act`), чтение страницы, вкладки, файлы (`files`), вопрос владельцу (`request_input`), отчёт (`report`), `kill_specialist` — какие нужны без входа и покупок. Как muse показывает страницу модели (снимок экрана, дерево доступности, текст) — найти в `runtime/pages.rs`, `tools/interaction.rs`, `runtime_read.rs` и повторить.
3. Chromium через CDP (крейт без openssl), свой профиль на окно (`profile`), окна живут между командами главного агента; на Mac в тестах — headless Chromium, если он есть, иначе тест пропускается с понятной причиной.
4. Завершение работы окна — `completion_gate` и `handoff` муse (`prompts/browser/completion_gate`, `handoff`).
5. Тесты: поддельная страница на 127.0.0.1 (форма, ссылка, вкладка) — исполнитель через цикл на обоих поставщиках проходит задачу и отчитывается; продолжение окна по `task_id`; вопрос владельцу и ответ `answer_to`; закрытие окна.
